The new full-domain audit leaves theoretical joint5% headroom in only four of thirty development prefixes, all in two families. A larger model or cleaner formatting confined to the old pool cannot change that bound.

1. Implement a separately versioned local-model proposal adapter using only the ten acquired examples and admitted feature domains. Any projection to a real unobserved configuration must use features only and be specified before generation. A proposed candidate must be eligible under the same manifest. Freeze representation, constraints, deterministic tie-breaking, duplicate/invalid handling, fallback, request/token/time/acquisition limits and the exact comparison before calls. Keep actual failed attempts in the denominator. Do not reuse old responses for changed prompts.
2. Run the bounded development assay across all six exposed families and fixed seeds, preserving equal paired B20 budgets. Compare full-domain sequential3NN, a single classical portfolio and matched cheap proposal/selection controls. Include random proposals under the same projection and retry budget to identify improvement due simply to changed search access. Source-acquired labels and V126 extrema remain evaluator-only. Any model sequential update must charge its outcomes and use only its own branch. Keep this an adaptation, not a claimed full SNAP2 or LLAMBO reproduction.
3. If the model adds useful benefit beyond those controls, freeze a model-matched controller with pre-decision features and development-only preprocessing/thresholds. Do not use uncertainty that requires LLM calls as a cheap pre-call feature. Then evaluate all required escalation policies on newly reserved independent system groups, keeping variants and seeds together. Do not choose those groups by their revealed headroom. A model lacking incremental value cannot be rescued by hindsight routing.
