# Research discussion note — local pilot, not a paper claim

**Current finding:** this small-model pilot has not established that benefit-aware LLM escalation improves software-configuration optimization. It has established a reproducible paired evaluation and identified failure mechanisms worth separating before scaling a router. Negative results here concern this model, formulation, tables and budgets; they do not refute LLM optimization generally.

The repository asks whether, after10 acquired outcomes, a controller can decide whether to spend its remaining10 evaluations on an LLM. The classical algorithm is an explicitly labeled paper-based nominal-centroid adaptation. SNAP2's exact artifact was not established; this is not a numerical replication. Primary-source and license checks are recorded in source_audit.md, admission_v6.md and THIRD_PARTY.md. The dataset and model versions, feature/target schema, raw prompts, acquired labels, costs and frozen protocols are saved.

The strongest existing routing evidence is v6:30 paired cases across six software families, split into three development and three test groups, with five fixed seeds per group. A development-fit gain predictor and its threshold were sealed before test acquisitions. On the15 held-out cases, the real local0.5B model materially helped twice and harmed three times at a fixed .02 normalized-loss margin. Always escalation had mean loss .074581 against .061505 for never escalation. The benefit and uncertainty controllers both chose zero escalations, so this evaluation does not show that benefit prediction can select useful calls. A matched-zero-rate random comparison is necessarily uninformative about ranking. Hindsight loss .055799 is a nondeployable upper reference, not a achieved routing result.

That result motivated a mechanism diagnosis. In v6,279/300 generated feature proposals copied observed prefix configurations, and289/300 required projection onto available unevaluated table rows. In the subsequent development-only v7 experiment, a decoder constraint eliminated original-prefix copies while keeping prompt and other treatment components fixed. All15 real model continuations completed; none materially improved and one materially worsened against each main comparator. Only7/150 new proposals matched recorded candidates directly. Missing table rows are not necessarily invalid software configurations. Syntax and prefix exclusion therefore did not establish useful exploration.

V8 freezes a different formulation: select ten existing rows from an acquired-label-only shortlist of20. Both random selection and static classical ranking use exactly that list; model IDs are randomly assigned. This removes projection but changes several treatment components jointly, so it tests the formulation rather than identifies one causal effect. The30 new model-free controls have completed and passed independent replay. The15 real-model cases are currently blocked by the exhausted113-request follow-up allowance; a specific increase to128 has been requested. Until they run, no V8 model effect exists to discuss. Start with pilot_report_v8.md for the latest completion state.

The evidence is sufficient for a small, candid methods discussion: real execution, explicit failures, fair per-arm acquisition budgets, grouped splits and a falsifiable next comparison. It is insufficient for cross-system generalization or publication-level claims about a learned router. Three test groups, a tiny single model, binary features, one target, one budget and exposed public data are material limitations. Development ablations must not be pooled as fresh test evidence. Results were not selected for being positive.

Questions to resolve at review:

1. Is there enough attainable LLM benefit to justify learning a controller, or should a stronger continuation mechanism be established first?
2. Is direct candidate selection the right offline task, and what stronger cheap baseline should define the opportunity cost of escalation?
3. Which new, independently validated software families and practical improvement margin would make a held-out test meaningful?

Recommended stopping rule for this pilot: finish the one frozen V8 comparison if its bounded allowance is approved, then stop adaptive treatment search and review all results, whatever their direction. Broad evaluation requires a separately specified untouched-system design. No email, submission or publication has been made.
