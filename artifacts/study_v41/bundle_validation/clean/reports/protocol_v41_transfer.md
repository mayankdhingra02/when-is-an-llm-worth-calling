# V41: prospective six-family recorded-table transfer

Status: frozen before new objective acquisition. Classical stage is authorized by existing limits. Model stage requires a separate exact extension; no authorization is inferred from this protocol.

Question: does candidate selection by either already installed local Qwen model improve a fixed ten-label classical prefix over strong cheap continuations on six additional families? This broadens external validity of the original escalation question. It is not a reproduction of SNAP2, and does not pool these single-target cases with size-constrained V38.

## Admission and scope

Select BDBC, Dune, LLVM, HIPAcc and SaC from the pinned DeepPerf registry, and OpenVPN revision 2.1.0 from the pinned PerformanceEvolution registry. One representative per family; BerkeleyDB variants and Dune/HSMGP variants stay together. The structured exposure audit excludes only two specifically reviewed metadata-only, zero-acquisition reports. Public model-pretraining exposure is unknown.

Dune fixes the recorded `cells` feature to the smallest available level, 50, before outcomes. This is a recorded encoding, not a claim that the physical problem has 50 cells. Keep all other registered feature values. For cost control use at most 1,024 configurations per family: choose the smallest SHA-256 digests of `{'salt':'v41','x':feature_tuple}` under the project canonical serializer, then restore source order. Subset selection is shared across seeds and arms and sees no objectives. It changes the search space and cannot establish performance on each full original table. The manifest binds every selected source line and feature digest.

Time targets are minimized; OpenVPN throughput is maximized. All report scores are relative to acquired comparator performance; no full-table oracle optimum or hidden-label normalization. No raw hidden labels enter search, prompt, ranking, feature extraction or routing. Numeric levels are nominal, as in V6. JavaGC is excluded because its 612-level feature cannot use the existing alphabet; outcome quality was not consulted. Other registry families remain deferred, not silently rejected for poor results.

Equal application utility is not established: database options can change services, compiler options affect optimization effort, solver settings can affect numerical quality, and VPN options affect security. These are recorded-target search experiments, not deployable configuration recommendations. Functional correctness, noise, workloads beyond the source benchmark and current software releases need a separate validation study. Data-specific redistribution permission for DeepPerf remains unresolved; use local cached data and hashes, no redistribution or publication.

## Collection

Seeds: 11, 23, 37, 53, 71. Thirty intended prefixes. Four initialization acquisitions followed by the existing nominal-centroid search to ten evaluations. Save exact state, RNG order, features, shortlist, prompt and hashes before any continuation. Each arm inherits that prefix and acquires exactly ten further outcomes, with isolated state. Seven classical controls: full-domain centroid; static shortlist rank; batch 3NN on shortlist; sequential 3NN on shortlist; sequential 3NN on the entire admitted domain; uniform shortlist selection; uniform entire-domain selection. 3NN uses nominal Hamming distance, mean acquired target and stable prefix/source-seed order ties. Maximization reverses predicted target rank. The primary LLM comparator is batch 3NN (same feedback and shortlist); full-domain sequential 3NN is a required strong-control comparison. No best comparator is chosen after seeing results.

Classical maximum: 30 × (10 + 7 × 10) = 2,400 new accesses; 210 arms, logical budget 20 each, maximum 300 seconds. Invalid outcomes count as attempts and stop collection with all intended cases retained. No replacement seeds/families. Raw acquisition journals precede state updates. No new live physical measurement.

Proposed model phase: both already installed, provenance-checked Qwen2.5-Instruct sizes 0.5B and 1.5B, 30 calls each, 60 maximum including any failures, no retries. Greedy CPU float32 with existing candidate-ID grammar, 20 output tokens, 30-second request timeout, no paid APIs, no downloads, USD0. One randomized candidate presentation fixed per prefix (same for both sizes); ten selections from a twenty-candidate shortlist. Existing V8 prompt text/representation is unchanged. No additional prompt variants selected after outcomes. Maximum 4,096 input tokens; overflow is an intended failed case, not truncation. Invalid/timeout outputs fall back to the frozen batch-3NN ten candidates, all failures retained. Maximum 600 new outcome accesses; 700-second stage inside unchanged global 3,600-second cap. All 60 prompts/token counts must be checked before requesting inference. This phase is disabled until an exact cap extension from 230 to 290 is granted and bound to the freeze.

## Analysis fixed before collection

Report each of 30 cases and equal-family means for each model separately. Positive relative gain is `(reference-treatment)/reference` for time and `(treatment-reference)/reference` for throughput. Primary comparator batch 3NN; also report all six others. Include wins/ties/harms, absolute acquired targets, prefix improvement, costs and failure denominators. For each contrast report a six-family bootstrap interval with 10,000 draws, seed 41000, and exact sign-flip enumeration on six family means. These are exploratory uncertainty summaries; six independent groups remain too few for broad claims. No seed-level independence and no significance hunting across comparators, models or metrics.

Evaluate never/always, sealed V6 benefit and uncertainty routers, random escalation at each sealed router's rate, and diagnostic hindsight oracle, without refitting thresholds on these new families. Old controller training used a different LLM interface and target loss, so this is explicitly policy transfer; a zero-call policy is not evidence of useful discrimination. No new learned-router tuning in V41. A future learned-router study needs new independent development and test groups and a new freeze. Cost sensitivity uses relative utility penalties 0, .01, .05 per call, clearly hypothetical rather than dollars. Count actual collection for all branches separately from the selected branch's retrospective deployment estimate.

Classical results may be inspected after this complete protocol, prompts and algorithm freeze. Any change to the LLM treatment, admission, controller, primary contrast or outcome analysis after that inspection requires a new exploratory version; do not label the changed procedure a fresh held-out confirmation. Preserve failures and all frozen artifacts. Stop for limits and finish independent verification, not substitute synthetic LLM outputs.

## Decision rule

Success requires a useful benefit that survives the strong controls across families and honest cost/reliability accounting. Neither a positive mean nor journal quartile determines success by itself. This is one empirical extension; novelty, application utility, an independent model family and broader generalization remain journal-readiness questions even if V41 is positive.
