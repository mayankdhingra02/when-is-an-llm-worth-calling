# Reviewer audit bundle (V178)

This bundle supports the manuscript *When Is an LLM Worth Calling? Rare, Concentrated Gains from Escalating Classical Configuration Search to Large Language Models* (`paper/overleaf_v173/main.tex`). It lets a reviewer recompute every result table offline from the saved case records, independently replay the saved LLM responses and charged acquisitions, and check the files against the project's original integrity manifests.

Nothing in it calls a model, an API or a benchmark. It contains no credentials, API keys or model weights.

**Private review copy.** Some included third-party tables have unresolved redistribution rights (see [Licensing](#licensing)). Please share this bundle privately with reviewers; do not post it publicly.

## Quick start

Requirements: macOS or Linux, Python 3.10 (the study used 3.10.13), and about 2 GB of free disk space once unpacked.

```sh
unzip llm_escalation_audit_v178.zip && cd llm-escalation-audit-v178
python3.10 -m venv .venv
.venv/bin/python -m pip install -r requirements-bundle-v178.txt   # the only step that uses the network
.venv/bin/python scripts/reproduce_bundle_v178.py
```

The last command takes about two minutes. It runs every check below and prints PASS, FAIL or SKIP for each. Then it re-hashes every bundled file and writes `REPRODUCTION_RESULT_V178.json`. Exit status 0 means:

- every core check passed;
- no data file changed.

Report and figure scripts overwrite their outputs in place, so "no data file changed" means those outputs were regenerated byte for byte. Figure files (`.png`, `.svg`) are listed separately if they differ, because rendering can depend on the fonts installed.

**Offline guard.** Every command is launched through `scripts/guarded_run_v178.py`. The bootstrap installs a network guard inside that Python process, then checks it: a loopback connection and a host lookup must both fail with the guard's own error before the command runs. The runner performs the same self-test first and stops, running nothing, if the guard cannot be verified. The check does not depend on Python's start-up files. (The V176/V177 bundles relied on an automatically imported `sitecustomize.py`, which a host's own `sitecustomize` can shadow; an independent audit hit exactly that.)

The guard covers each command's Python process, not processes those commands start. Every child launch is recorded in `REPRODUCTION_RESULT_V178.json`. In the reference run they were:
- matplotlib's font-discovery tools (`fc-list`, `system_profiler`);
- Python 3.13 running the host-dependent EZR bridge tests;
- the guard tests' own subprocesses, which themselves run through the bootstrap and are therefore guarded.

## Environment: numerical agreement vs. exact reproduction

The reference environment is Python 3.10 (the study used 3.10.13) with the packages pinned in `requirements-bundle-v178.txt`. The runner records whether you are in it: the Python version and any package that differs from its pin.

Byte-identical outputs and exact trajectory replays are expected **only** in the reference environment. With other versions, floating-point summation order can change values at about the 1e-15 level. Some replays choose among nearly tied configurations, and there such a difference can flip the choice. Exact-match checks can then fail even though the recorded observations are unchanged.

An independent audit on Python 3.13 with newer NumPy/SciPy reported both effects:
- 27 numeric fields differed by at most 7.1e-15;
- a few replays chose a different configuration among near-ties.

It also reported recomputing the paper's headline numbers from the saved observations with its own code, and they agreed. A failure in a non-reference environment therefore means the environment differs; it does not show that a result changed. For exact reproduction, use Python 3.10 with the pinned packages.

To skip the host-dependent check, run `scripts/reproduce_bundle_v178.py --core`.

## What this bundle cannot reproduce

- **Model outputs.** Model responses are replayed from the saved raw responses, not regenerated. Hosted inference is not deterministic, and the local models' weights are excluded.
- **Native timings.** These are the saved measurements. Timings depend on the machine, so they cannot be re-measured from the bundle.
- **Four raw re-validation checks: not rerun by this offline workflow; original-workspace execution receipts included.** Each receipt (`artifacts/study_v1xx/replay.json`) records a run in the original workspace. It is a record, not a re-verification, and the reproduction never reports these checks as passed. They cannot run here because the bundle omits their pinned runtimes or data:
  - `verify_native_study_v153` hashes memcached and libevent binaries.
  - `verify_apps_v168`, `verify_ezr_v169` and `verify_ezr_v170` import the pinned Polars and XGBoost native runtimes (125 MB) and read the Covertype and flights data.
- **The full seal chain.** `seal_research_v177.py --verify-only` needs every file ever sealed, including model weights. `verify_bundle_v178` checks everything included instead. For an omitted file, the exclusion list gives its sealed hash; that hash says what the file should contain, but nothing in the bundle can confirm it.
- **One test and one verifier comparison.** Both compare the recorded llama.cpp command, which embeds the original absolute project path. `verify_v172_relocated_v176.py` runs the unchanged verifier with that path recovered from the recorded commands themselves. The one pytest case that makes the same comparison is deselected.
- **The compiled PDF.** No LaTeX toolchain was available when the bundle was built. Compile `paper/overleaf_v173/main.tex`; the bibliography is embedded.

## Integrity and earlier seals

`BUNDLE_MANIFEST_V178.json` lists the SHA-256 of every file in the bundle.

The project sealed each stage with an evidence manifest (`artifacts/*/evidence_manifest.json`). All 88 manifests are included exactly as originally written; none has been rewritten. `verify_bundle_v178`:

1. checks that the latest sealed manifest (V177) and every earlier manifest it names by hash are present, a chain of 77 checkpoints;
2. for every file those manifests seal, either finds a copy with the sealed hash, or records why the file is absent.

A copy counts if it is at the file's own path, at the redirect recorded by the V177 seal, or in a `previous_snapshot/` copy. Absent files are listed in `EXCLUDED_FROM_BUNDLE_V178.tsv` with their sealed hash, size and one of these categories:

- model weights;
- third-party runtimes and native build trees;
- earlier packaged bundles;
- third-party source archives;
- earlier or unrelated iterations (V1–V140, except the V131–V136 records the paper cites, and side studies);
- workflow notes;
- raw data not read by the checks;
- other files not needed for the paper;
- superseded versions.

A present file that differs from its seal, with no recorded supersession, would be reported as an integrity failure.

Old `STATUS.md` copies for every stage are under `artifacts/*/previous_snapshot/`. Freeze records, amendments and deviation logs are under `artifacts/study_v1xx/` and `reports/protocol_v1xx*.md`.
