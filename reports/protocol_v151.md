# V151: exploratory rare-benefit prediction and ecosystem sensitivity

This version reuses all70paired cases/model from eight already exposed execution-engine families (V147 plus V148). It is **exploratory development**, not an untouched confirmation. It will retain every declared variant, harm and fallback. No new objective acquisition, model inference, package/model download or paid/cloud work. Analysis wall cap600seconds, one process. Existing collection allowances stay closed. Prior evidence is verified and mutable-root files snapshotted before changes.

Question: do richer prefix trajectory features or small nonlinear predictors improve selective escalation, and is any apparent transfer dependent on treating Spark and Hadoop as independent? Target is relative gain of the LLM arm against sequential3NN. Practical benefit/harm margin remains1%. Joint >1% improvement against sequential and adaptive is a secondary diagnostic, not the target or a free deployable portfolio.

Inputs: same B10prefix, same saved B20branches, model identities, usage and fallback status. Preserve previous models separately. All transformations use only ten acquired positive labels and feature-only domain summaries; no source-table objective reads, system/workload IDs, model responses or continuation metrics enter features. Previously exposed paired gains are training targets only. Prefix-only new features are fixed before this run: log spread, relative IQR, oriented best-to-median log gap, early/late incumbent log progress, best-to-second log gap, unique label fraction, time-versus-oriented-log-label correlation, oriented last-five versus first-five log mean, first-four CV, and high-tail fraction. In addition retain original seven features. Ratios/log differences are unit invariant. Direction is explicit.

Fixed candidate predictors: original seven-feature ridge(alpha1); extended18-feature ridge(alpha1); extended shallow regression tree(depth2, minimum5cases and2families per leaf, weighted squared-error splits at training quartiles); extended RBF kernel ridge(alpha0.1, training-standardized features, kernel exp(-mean squared standardized distance/2), family-weighted fit). These four are not a post-hoc hyperparameter search. Predictions are direct expected relative gain, not calibrated probabilities. Equal family weights; training-only scaling. Fixed settings trade flexibility against the tiny number of groups; no model-size conclusion follows.

Nested leave-one-group-out evaluation: outer test group excluded from every fit and threshold; inner group folds produce development scores. Threshold grid: zero plus weighted score quantiles0,.25,.5,.75,1 and never-call. Maximize family-mean realized gain on inner development predictions, ties fewer calls then higher threshold. Meta-selection among the four variants uses only these inner utilities, ties fixed listed order; never-call remains available. Report all variants separately, even if meta-selection loses. Also report development80th-percentile score policies for all four, uncertainty calibrated/80th-percentile, never/always. No threshold fit on held-out scores or outcomes. These tests assess new outer predictions, but the whole design uses previously inspected data and remains exploratory.

Run two declared grouping analyses: (1)eight execution-engine families; (2)seven ecosystem groups, merging Spark and Hadoop while retaining every variant/seed in their group. No selecting the grouping that looks better. Primary comparator is never-call (zero relative gain). Matched-realized-rate random expectation is computed per held-out group as selected_fraction times mean gain; label it a retrospective diagnostic, not an online policy. Save one fixed-seed matched random selection and full decisions. Report equal-group and pooled gains, rate, harmful/useful/joint calls, missed benefit, observed selected tokens/time with unknown usage explicit, and leave-one-group-out aggregate ranges, not small-sample significance or independent-seed confidence intervals. Diagnostic family-local AUC for >1%benefit, only when both classes exist, measures ranking rather than probability calibration. Hindsight best arm is an upper reference only.

Protocol and input hashes freeze before running. Tests must reject held-out target influence, prefix shape/invalid values, training/validation overlap and corrupted inputs; features must be invariant to positive unit scaling. Retain raw fits, training/validation memberships, scores, threshold grids, predictions, policy summaries, runtime, deterministic figures and replay checks. A revision that looks best here is only a candidate for a later frozen fresh-family study, not a rescued positive held-out result. No further requests/acquisitions are authorized by this analysis protocol.
