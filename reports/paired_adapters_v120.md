# V119–V120: a real opportunity, but the transferred router missed it

The constrained Qwen3-8B adapter selected configurations with lower mean published latency than all four fixed classical controls on the WordCount table. Two of five prefixes improved by at least5% against both co-primary controls. The frozen benefit-aware controller escalated in zero cases and therefore missed both joint opportunities. This is evidence of an opportunity in this recorded table, not a successful benefit-aware controller or a journal-readiness guarantee.

## Scope and sequence

V119 chose the original owner WordCount table by its feature/workload semantics and froze its source, protocol, implementation and all controller masks before continuation outcomes. Available exposure auditing found no previous Storm objective results. It deliberately restored the limited published-label scope already used by the older recorded-data studies; it did not loosen V52's stronger correctness/measurement admission gates. Original latency semantics, per-run success and executed-version provenance remain unverified.

All five V119 real responses produced five-character configuration strings instead of candidate IDs and failed the frozen parser. Each case used its predeclared classical fallback. V119 quality differences therefore compare that fallback with other controls: they do not measure successful LLM choices. The original generated V119 figure uses the generic term "LLM arm"; read it specifically as an all-fallback policy. No failed answer was reinterpreted, silently repaired or discarded.

After seeing these failures, V120 froze one follow-up using the existing V91 grammar-constrained greedy adapter. It reused every saved prefix, shortlist, message, classical reference and router decision. All50 real one-token requests returned valid IDs, yielding five complete continuations without retries. V120 is exploratory on an exposed table. Grammar, decoding settings and template handling differ together, so the validity/quality change cannot be attributed to grammar alone. It is not a measured automatic repair policy.

The practical-margin criterion fixed before V120 collection was met: positive mean against both co-primary controls and at least one joint5% win. Seed71 was worse than batch/sequential/portfolio, seed23 tied all controls, and seed53 improved against batch but lost against sequential. All remain in the analysis. No interval/p-value is calculated from five correlated seeds as though they were five independent systems.

The old V6 benefit and uncertainty policies both escalated zero times. Their training model and normalized-loss target differ from this Qwen/relative-gain task; they are unchanged transfer diagnostics, not newly fitted estimators. Their zero cost is accompanied by missed improvements. Matched-rate random at zero also never escalates, giving no useful discrimination test. Hindsight headroom is descriptive and non-deployable.

## Actual research cost versus deployment estimates

Both adapters together: **55 real requests**, **350 charged recorded acquisitions**, 350 generated tokens/690 allocated, 7884 reported prefill tokens and 52.674s summed server lifecycle time. Five initial format failures plus five valid constrained continuations. No retries, missing response usage, cloud calls, new downloads or external spend. All servers stopped. The request count includes every failed-format answer.

The350 acquisitions are50 shared prefixes +200 classical branches +50 initial fallback branches +50 constrained branches. Every logical optimization arm remains B20. Replaying already acquired cells for integrity checks does not acquire labels for a selection algorithm. These are recorded-table accesses, not350 fresh Storm executions.

V119 lifecycle 32.480s, peak RSS 5,921,718,272bytes; V120 lifecycle 20.194s, peak RSS 6,196,396,032bytes. V120's mean sum of request wall time per continuation was 3.851s; excludes startup, controller/oracle overhead and native application costs. Request-level prefill is smaller under cache reuse; token counts are not evidence of equal work per request across adapters.

Estimated deployment uses one prefix and one selected branch. V119 allocates one model request/escalation; V120 allocates ten. We collected both plus all controls for research; these costs are not erased. No inference-dollar tariff or native wall-time break-even is claimed.

## What this changes and what remains

Earlier exposed-family practical-margin failures do not justify a universal claim of no LLM opportunity: this WordCount table now supplies a counterexample under a different existing adapter. It does not retroactively validate the original free-output interface or justify selecting favorable systems. Keep the older six-family results, the new external format failure and the exploratory positive continuation separate.

The most important next experiment is to freeze this exact constrained adapter and a group-disjoint development/evaluation plan on additional software families, selected by source/feature eligibility before opening targets. Keep all Storm variants out of any purported new test group. Fit a controller for this exact model/interface/relative-gain target only on development groups, with a never-escalate default where cost-adjusted evidence is weak. Do not refit on these five seeds and call the result held-out. A causal adapter ablation and native measurement replication are separate subsequent questions.
