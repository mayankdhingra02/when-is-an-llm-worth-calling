# V133: prospective lossless-JPEG extension with a domain-specific cheap control

Freeze before any native objective measurement. This is a new libjpeg-family native task, selected by documented exact-pixel semantics and source/data availability, not by favorable outcomes. Related IJG/libjpeg-turbo versions, all three pictures and all seeds are one group. Existing systems remain exposed. One family cannot establish population generalization or Q2 readiness. This is an independently implemented native adaptation, not exact SNAP2 replication.

## Contract and data

Owner libjpeg-turbo tag 3.1.2, static local cjpeg/djpeg build with Xcode clang/SDK 15.5; no system install. Original IJG/BSD/zlib notices retained. Three fixed real scikit-image v0.20.0 RGB photographs: astronaut (NASA, public domain), coffee (Rachel Michetti, CC0), rocket (SpaceX, public domain per dataset owner's attribution). Verify all three against the source owner's SHA256 registry. These are known public test images, not evidence of absent model pretraining contamination. Decode once using pinned Pillow 12.3.0 and save complete RGB PPMs; no resize, crop or color conversion. Rocket is already a JPEG: the exact reconstruction target is its decoded RGB pixels, not the unknown original camera samples.

Minimize the sum of output JPEG bytes across the three images. Every setting uses predictive lossless JPEG, eight-bit precision, point transform zero, automatic optimized Huffman coding, no DCT/quantization/quality reduction, no subsampling, smoothing or color-space conversion. Reconstruct each output with a separate djpeg process and compare every RGB byte, mode and dimensions to the saved source. Same-library decoder is a limitation, not independent-implementation certification. No timing target: wall time is collection overhead only.

Finite domain 70: predictor 1..7 × restart rows {0,1,4,16,64} × scan layout {single interleaved RGB scan, three separate R/G/B scans}. Each scan script explicitly sets predictor, Se=0, Ah=0, point-transform Al=0. Layout does not drop/reorder pixels. Restart changes are permitted only because the task promises correct-file reconstruction, not robustness to transmission corruption. Decoder support for lossless JPEG is required; no browser/deployment compatibility claim. Huffman optimization is automatic in lossless mode, so it is not a fake tunable axis. Arithmetic coding and ignored lossy knobs are excluded.

Reference (7,0,0), neighbor-average predictor, is a fixed reasonable reference, not a claimed strongest setting. Default anchor (1,0,0) is the simplest left predictor in the lossless task, not ordinary lossy cjpeg defaults. To guard against weak anchors, include a **predictor-sweep arm**: all seven predictors at zero restarts/interleaved, then all seven separate-component counterparts, skipping acquired rows; fill remaining continuation slots with prefix-ranked 3NN if necessary. It is a cheap domain-knowledge comparator with all observations charged.
