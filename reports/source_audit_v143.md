## Tuneful admission and limitations

Selected before any objective conversion: Bayes/bigdata100rows, PageRank/huge99, Terasort/ds1 100, TPC-H/20 100, Wordcount/bigdata100. All distinct configurations within fixed workload, input and cluster. Five workloads count as **one Spark system group**, with all seeds together. Full source files include additional contexts; they remain unacquired. Source names, hashes, physical row IDs, raw feature values, scaling bounds and categorical domains are saved in V144 candidate manifests. Selection uses named initial workload contexts, never performance. One PageRank context has99records; no invented100th run or failure status.

Crucially,`dataset/*features*`files contain **post-execution telemetry**. Only headers were inspected; none of those fields enters optimizers/prompts/routers. For experiment tables only first30columns are settings; App/input select a fixed context, App_id is excluded, target column30 is reserved for charged oracle. TPC-H has four unlabelled trailing columns, three nonempty cells in one selected-context row; these are counted and ignored, not parsed or used. All intended selected rows remain. Blank/other-context rows are excluded by context, not outcome. Source-wide failure denominator, repeated-run noise, correctness and collection chronology are not certified; results concern the recorded support.

The author paper describes Apache2.0 for implementation, but neither data nor code tree contains a top-level license. Treat dataset redistribution rights as unresolved. Private analysis only; no full source tables in a shareable replay bundle and no public release. Upstream code is read, never imported/executed. Spark encoded categories are kept as source labels; no guessed codec-number meanings. Numeric settings are normalized by feature-only min/max. A ten-level model proposal grid plus exact recorded-prefix normalized coordinates is an explicit output-capacity adaptation; random grid proposals provide a matched representation control.
