# V79 workload admission audit

Primary source inspected: [Sebastian Deorowicz's Silesia corpus page](https://sun.aei.polsl.pl/~sdeor/index.php?page=silesia), retrieved2026-09-26. This is a standard compression corpus, not a newly collected production workload. Direct files from the same university host were downloaded; archive and raw SHA256 recorded, raw sizes and published MD5 checked. No third-party mirror was substituted. No downloaded content is executable in this study.

Selected before any new Kanzi outcomes: dickens (plain text,10,192,446bytes), sao (binary catalogue records,7,251,944bytes), xml (structured markup,5,345,280bytes). The criterion covers three content categories within5–11MiB without slicing. The owner's page is inconsistent about the XML file count, so that count is not relied on. Data versions are fixed by exact hashes, not the mutable page.

No blanket corpus redistribution license was established from the owner page. Source attribution is recorded; raw files remain in ignored data/raw and are excluded from shareable artifacts. This does not establish permission to relicense or redistribute the data. A public package would need a retrieval recipe and a separate rights review, not an invented permissive license.

These are three workload variants of ONE Kanzi system. They add input diversity but no new independent software family. The new comparison uses no model and does not measure LLM transfer or benefit prediction. The preset choice was informed by exposed V78 results. Its prospective performance on these fixed new files is a bounded classical follow-up.

Download evidence: artifacts/study_v79/download_ledger.json and workloads.json. Initial sandbox DNS denial transferred zero payload bytes; the same owner-only script succeeded with network permission.8,181,238new bytes; no model downloads/spend. Source metadata/source-code reading is not an objective evaluation.
