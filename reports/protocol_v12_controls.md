# V12: measured cheap controls for the revised size-constrained task

Exploratory classical-only study following V11. It does not establish LLM value or replace prior outcomes. Use all ten Brotli/lrzip development cases, the same revisions and fixed seed list. No subset selection, no held-out data and no model calls. Freeze code/data/input hashes before collection. Both algorithms have total20 acquired configuration vectors including ten-prefix evaluations.

Restore the original V6 prefix row order, but reacquire/charge each of its ten rows as a runtime-and-size vector before any size-aware decision. A configuration acquisition returns both fields under a declared one-vector/one-charge rule. The prefix is shared once between the new pair; previous historical costs are retained. Actual new accounting is10 joint prefix accesses +10 per continuation per case =300 charged vector accesses for10 cases. These may revisit previously recorded rows; do not call them300 unique new software measurements. This is an offline recorded-table experiment.

The cap is the output size of the first fastest-runtime prefix row. It stays fixed. Both branches retain their best acquired row satisfying the cap; the prefix anchor always remains feasible. Candidate space is the entire unobserved recorded feature table, addressing the restricted-shortlist concern. Source-table targets are accessible only through an acquisition oracle during selection; full-table scoring is separate.

Control1: adaptive **joint_3nn**, an ordinary cheap deterministic reference, not claimed state of the art. For every available candidate, use nominal Hamming distance to acquired rows; take its three nearest acquired neighbors, ties in acquisition order; predict mean runtime and mean size. Among candidates predicted size-feasible choose smallest predicted runtime, ties in saved prefix shuffled order. If none is predicted feasible, minimize predicted size then runtime then saved order. Acquire the chosen row's true pair and repeat. No hidden scaling, true-size prefilter or uncharged probes.

Control2: random full-table continuation, next available row in the same original seeded shuffled order. Both branches independently clone prefix IDs/joint labels and acquire ten more. All failures/partial cases remain in the20-branch intended denominator; started incomplete cases refuse automatic retry. Persist each actual access before parsing/using its targets. Repeat runs reuse completed cases, never delete/reset ledgers.

Evaluate raw relative runtime differences between the new feasible incumbents. Report all ten paired cases, per-family means, actual infeasible acquisitions and descriptive strict gain thresholds0%,5%,10%,20%; no threshold is called a validated application margin or selected to make the result positive. Joint size/runtime semantics and measurement-noise/correctness limitations from V11 apply. After both branches complete, compute exact full-table feasible bound for context only. No iterative model/hyperparameter/prompt search follows the outcomes.

Original source/feature provenance remains frozen. Experiment runtime and any repeated analysis are charged to the existing1800-second ledger (about129seconds remain); request count stays128, no new inference allowance, no downloads/spending. Stop/retain incomplete denominator at a cap. This new constrained baseline is exploratory feasibility for a future model comparison, not a positive learned-router experiment.
