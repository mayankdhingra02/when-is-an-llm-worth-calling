# V5 preparation boundary

The new finite-domain implementation is a component prototype, not a full frozen experiment. It preserves explicit hidden-label boundaries and inclusive budgets, uses modal centroids with stable ties, and treats every observed level as nominal. Changing numeric distances, encoding, model prompts or candidate limits changes the treatment and must precede new outcomes in a versioned protocol.

Outstanding requirements before collection:

1. Admit semantic primary targets and valid workload/revision representatives; objective columns not selected remain hidden, never features.
2. Freeze all family assignments and selected table hashes. Retain conservative related-product groups and exclusions of old Apache/SQLite/x264 families.
3. Implement and test a real finite-domain local-model serialization/decoding interface with provenance, strict invalid handling and existing resource guards. The codec helpers alone are not that adapter.
4. Implement the full grouped collector with paired prefixes, checkpoint/resume integrity and failure denominators; seal controller fits before test outcomes.
5. Obtain a concrete explicit resource allowance for the admitted run. Nothing in this snapshot authorizes more than the remaining existing allowance.

Existing v4 and its actual measurements remain unchanged. All executions of the new finite optimizer in this session were synthetic unit tests. The registry snapshot establishes reproducibility of the audit and preparation only.
