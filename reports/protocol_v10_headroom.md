# V10 retrospective headroom check

Question: do the existing fifteen development cases offer enough possible improvement to justify a stronger-model rerun? No new inference, optimization, acquisitions, held-out tuning, downloads or spending. This is post-hoc feasibility analysis over saved outcomes, not a new measured arm or a preregistered confirmatory test. Existing models/thresholds/outcomes remain unchanged.

Use all three V8 development systems and all five seeds. Primary cheap comparator is the fixed V8 static-shortlist ranking, a measured implementable baseline. Also report adaptive classical, the observed LLM, and V9's exact uniform-subset expectation (an analytical reference, not a measured deterministic arm). Never select the best measured baseline separately per case and call that deployable.

For each saved prefix, the ideal same-shortlist terminal loss is the minimum of the prefix incumbent and the best of its20 candidates. A ten-selection budget can include that row, so this is an attainable-in-hindsight bound if labels were known, not a deployable method. Also compute the best recorded full-table terminal loss; one of the remaining ten acquisitions could include it, but using hidden values to find it is forbidden online. These upper references are evaluated offline only. Full-table and shortlist bounds answer different questions; do not conflate them.

Headroom equals comparator loss minus bound loss. Retain negative values where a restricted shortlist cannot match an unrestricted comparator. Count potential material improvements strictly above the existing .02 normalized-loss margin, per-case and per independent family; report equal-family means. Do not lower the margin to manufacture opportunities. Sensitivity at .005, .01 and .05 is descriptive only, with no threshold selected from it.

Inspect raw primary-target reductions as a secondary measurement-validity diagnostic: for positive minimized runtime targets, relative reduction is (comparator raw target - oracle raw target)/comparator raw target. Report source-provided unit meanings without inventing units. Explain that global min–max loss can compress useful relative runtime changes when the worst recorded configuration is very slow. This diagnostic cannot change the frozen success metric or establish matched compression quality/size across configurations.

Record table minimum/median/maximum and material-margin equivalent .02*(max-min). Compare shortlist bound with existing V8 hindsight results and V9 exact-distribution minima as independent saved cross-checks. Verify raw-to-normalized values and comparator source labels, keeping original freeze hashes intact. Mathematical synthetic tests must cover minimization/maximization, incumbent clipping, strict-margin behavior and nonpositive target handling.

Decide whether another same-design model run is worth proposing from the observed breadth of attainable material benefits versus the fixed cheap comparator, rather than from a desired positive result. Concentration in one development family is insufficient motivation for cross-system router training; this is a resource-allocation judgment, not a statistical guarantee or impossibility theorem. If headroom is weak, stop the same-design stronger-model rerun and identify whether shortlist or metric validation must precede a redesigned study. No new resource increase is inferred.
