# V166 feasibility measurement contract

Freeze code, data, runtime hashes and the full schedule before executing any native configuration. Twenty outcomes per application: four predetermined candidate IDs repeated five times in shuffled blocks (seed 16602). Forty outcomes and eighty query/training executions maximum; 1800 seconds stage and 60 seconds per process. No warmup, retries, model calls or discarded failed attempts. Startup/input-loading wall time retained separately. Repetition occurs only for this charged feasibility study, outside any later policy B20 budget.

Polars domain: 64 combinations of 1/2/4/6 threads, in-memory/streaming execution, predicate pushdown, projection pushdown and common-subplan elimination. Bundle the three fixed flight queries in one collect_all call. Objective time includes CSV scanning/parsing and all queries, excludes Python import and constructing lazy plans. Compare every sorted integer/string output against the existing independent Python reference. Check requested vs actual thread pool. Common-subplan flags are requests to the optimizer, not a guarantee of a distinct physical plan; some settings may be equivalent.

XGBoost domain: 128 combinations of 1/2/4/6 threads, max_bin 32/64/128/256, max_depth 3/6/9/12 and 16/32 boosting rounds. Fixed CPU histogram, eta .3, seed16601 and seven-class softmax. Real Covertype rows are permuted once; first65536 train, next8192 quality-validation, remaining507284 unused. Training labels serve the application; optimizer/LLM will receive only acquired runtimes/quality, never unacquired configuration labels. Objective includes DMatrix construction, training and validation predictions, excludes imports/input-file loading. Quality requires accuracy>=.75. Preserve all8192 predictions, model digest and native configuration. Independent replay recomputes accuracy; it does not independently prove XGBoost algorithm implementation. This is software training configuration under an accuracy constraint, not a classifier-generalization study. Invalid quality has fixed60-second utility penalty in later optimization, never silently removed.

Admission: all20 intended native outcomes must complete with finite positive runtime and correct schema/configuration. For Polars all outputs must exactly match references. For XGBoost every prediction must have valid shape/class and independently matching accuracy; low accuracy is a quality outcome rather than a software failure. At least two of four fixed cells must have all five quality-valid repetitions, median objective runtime>=10ms and relative median absolute deviation<=5%. Otherwise retain a failed admission, without adjusting thresholds to obtain a positive result. No LLM outcomes influence admission. These timing/quality measurements expose both tasks for development; later repeated seeds do not provide new independent systems.
