# V164: prospective development intervention on proposal interface

This is an exploratory mechanism experiment on the two already exposed V163 application families, not a new held-out cohort, not a new router fit, and not a promise of a positive finding. Motivation observed in V163: many model proposals were repeated/projected and ANN continuations seldom improved the prefix. Frozen before new inference/outcomes. Prior evidence remains sealed.

## Comparison and allowed information

Reuse the exact ten saved V163 prefixes, five fixed seeds per application, and unchanged candidate domains/workloads/output validation. Historical prefix acquisition costs remain recorded and explicitly reused (100 outcomes, 300 native invocations); no rereading of hidden objective values. All continuation searches and validations are fresh. Models are unchanged pinned SmolLM3-3B and Qwen3-8B Q4_K_M, llama.cpp b11146, temperature0.7, top_p0.95, same within-case seed164000+seed across interfaces, no cross-device or shared-random-number guarantee. No model download or API spending.

Per model compare (1) the original V163 numeric prototype prompt and grammar, byte-identical messages; (2) explicit catalog prompt listing all54 eligible configuration IDs and feature values, with the same ten acquired labels, objective and budget. Grammar permits only eligible two-digit IDs, ten outputs. Duplicate IDs resolve using the SAME feature-space nearest-unseen projection and seeded tie break as the numeric interface. Invalid/incomplete/missing responses fall back to sequential3NN, keeping all intended cases. First seven proposals are evaluated; all proposals/repetition/projection are logged.

This is a **compound interface intervention**: explicit enumeration, candidate-ID output and constrained eligible membership change together, including prompt length. It does not isolate representation encoding alone. Catalog features contain no hidden objective or rank. No LLM receives either continuation's outcomes. Numeric/catalog jobs are interleaved in a fixed shuffled order per model. Models run serially, then native searches; no native measurements overlap model inference.

Five fresh classical controls stay unchanged: sequential3NN, adaptive neighbor, fixed-length1 GP-EI, randomfull, randomproposal. Same cloned B10prefix, seven fresh search outcomes, three fresh incumbent validations per arm. Ten cases ×nine arms=90 logical B20 arms. All90 incumbents frozen before three shuffled validation blocks. Prefix values are historically acquired measurements; equal reuse across arms does not remove temporal cache/load drift, disclosed in interpretation.

## Primary outcomes and analysis

Primary descriptive interface contrasts within each model/application: relative median-validation gain `(numeric-catalog)/numeric`; >10% practical improvement requiring distinct selected configurations, all three quality-feasible validations, MAD<=5%, both medians>=10ms. Report all five seeds, per-family means, losses and same-setting counts. Compare each model/interface secondarily with all five classical controls; joint robust wins require the same rule against sequential/adaptive/GP. No population p-value, equivalence, significance, or Q2-readiness inference from two groups. Do not pool earlier heterogeneous designs.

Mechanism endpoints: among the first seven evaluated proposals, nonzero projection and duplicate counts; all-ten-proposal counts separately. Report raw response validity, missing/failed intended cases, tokens, runtime and selected-prefix incidence. Lower projection does not imply better optimization or establish a causal mediation claim. Do not refit a router or select a winning threshold/prompt after outcomes. Saved historical policies are not validated for this changed interface.
