# Frozen larger-study design v4 — 2026-09-24

Status: **design frozen; larger collection admission blocked**. The user's “do it” authorizes the proposed registry/protocol/projection-control work. It does not silently replace the existing numeric inference/runtime caps. This document also freezes a bounded, model-free diagnostic on already exposed v3 systems before that diagnostic runs. No new-system objective outcome was inspected to select this design.

## Question and treatment

Does a development-trained predictor of incremental LLM benefit select better continuations than uncertainty or random escalation on untouched software-system groups, after a classical ten-label prefix? Is any observed LLM improvement also obtained by a model-free proposal generator using the same feature-space projection?

Keep the v3 treatment fixed: B=20, checkpoint t=10, four initial random acquisitions, adapted centroid search, greedy official local Qwen2.5-0.5B-Instruct at revision 7ae557604adf67be50417f59c2c2f167def9a775, binary legal-token generation, five proposals per call and two calls per continuation. Keep acquired-only optimization scaling, feature-only nearest-unevaluated projection, seeded tie order, and the offline normalized d2h evaluator. This remains an adaptation, not a SNAP2 replication. Do not change model, prompt, projection, margin or thresholds after new test outcomes are available. Real feasibility fixtures count in model cost, never in software quality.

## Eligibility and grouping

The immutable candidate inventory is data/registry_v4.json, backed by pinned MOOT commit 90803be51b00f881305db45aa0cf6a3b5340804f, SHA-256 and Git blob checks. The audit reads feature values and objective column names only, not objective payloads. Require source-named software identity, 1–39 binary features, one direction-marked objective, 20–5,000 unique feature vectors, and finite complete features. Keep first source row per duplicate feature vector, independent of outcomes. Semantic objective orientation, finite objective payload validation and the link to the original workload must pass a precollection data gate; unresolved direction or transformation excludes a table before any optimizer scores are inspected. The current candidates are schema-eligible, not an endorsement of all upstream provenance claims.

Exclude all Apache HTTP Server, SQLite and x264 variants from the larger study, including MOOT systems/x264.csv. These groups were already exposed in v1–v3. Quarantine HSMGP, SS-A–SS-X and rs/sol/wc variants until their actual underlying systems are verified. Do not infer independent groups from filenames, row counts or anonymous labels. A shared candidate matrix is a conservative overlap warning requiring provenance review, not proof that systems are identical. Group all versions, workloads, variants and seeds together. Multiple tables from one system never increase the group count.

Target exactly 20 independently verified, untouched eligible systems, with one representative table per group chosen lexicographically by pinned upstream path among eligible tables. If more than 20 qualify, order canonical groups by SHA-256 of `v4-group-split-20260924:<group>` and take the first 20. Assign the first eight to test and the remaining twelve to development. Five seeds per table: 11,23,37,53,71. Freeze the final selected file hashes and group map before acquiring outcomes. At present only four schema-compatible untouched named groups qualify, so **no split is issued and no larger collection may begin**. This is a feasibility finding, not a failed optimization result. Twenty groups is a planning target, not a power calculation.

Any addition of a new source, provenance resolution, or support for numeric/categorical or multiple-objective data requires a versioned registry amendment before outcomes. Broadening representation also requires a new treatment protocol and synthetic tests; it cannot be slipped into this binary treatment to reach the target count.

## Arms and model-free projection control

Each group/seed has plain random search from initialization (20 labels) and a centroid arm (20 labels). Save the centroid state, acquired labels, feature vector, row order and integrity hash at t=10. Clone it for each of:

1. Classical continuation: ten further centroid acquisitions.
2. Real LLM continuation: two batches of five proposed configurations; ten charged acquisitions after projection.
3. `uniform_domains_projection_v1`: independently sample each coordinate uniformly from its observed feature domain, including constant domains; two batches of five; apply exactly the same nearest-unevaluated projection, distance, tie order, duplicate and collision logging. RNG seed is the first eight SHA-256 bytes of `uniform_domains_projection_v1:<dataset SHA-256>:<seed>` interpreted big-endian. This branch consumes no model calls/tokens and is never labeled an LLM experiment. It does not read acquired objective values when proposing or projecting. State still retains the incumbent and acquired outcomes for normal scoring/accounting.

All acquired outcomes, including initialization and any future probes, are charged. Each arm has a logical budget of 20. One shared prefix yields actual collection of 20 random + 20 centroid + 10 LLM + 10 projection = 60 label accesses per group/seed, or 6,000 for 20×5. Repeated accesses across branches remain charged. No reliability feature acquires additional labels. Branch RNG/state never shares post-checkpoint information.

## Controllers and primary analysis

Retain the existing ridge model (alpha=1), group-weighted StandardScaler and predecision features, plus no-uncertainty and uncertainty-only gain-prediction ablations. Development predictions for threshold fitting are leave-one-system-out; every preprocessing fit is confined to that fold's training groups. Refit the selected model on all development groups only, then seal its weights/threshold before reading test continuation outcomes. IDs, hidden extrema, post-decision token lengths, runtime, failures and either continuation's quality are forbidden input features.

Use fixed benefit thresholds [-0.02,0,0.02,0.05,+infinity]. As in v3, choose the lowest development escalation fraction whose system-weighted loss is at most always-LLM loss +0.02; break ties by lower loss then grid order. If none qualifies, choose minimum development loss, then rate. Uncertainty thresholds are development quantiles [0,.25,.5,.75,1] plus infinity, with the same selection rule. This is an empirical criterion, not a risk or non-inferiority guarantee.

Report never, always, benefit, uncertainty, both ablations and random at the development-selected benefit rate. Fix random seed 20260924 independently of outcomes. Also report a diagnostic that selects exactly the benefit policy's realized test count uniformly without replacement (1,000 prespecified random draws, seed 20260925), and separately the analogous uncertainty-count diagnostic. This averages random comparator variability; it does not choose the best draw. Realized-rate matching is retrospective and not claimed as an online policy. If a rate is zero or one, explicitly call the comparison degenerate. The hindsight oracle selects the lower-loss arm after observing both; it is a non-deployable upper reference. Projection control is an optimizer ablation, never inserted as a fake LLM response in router training.

Define gain = classical loss − LLM loss and model increment beyond projection = projection loss − LLM loss. Material benefit is gain >0.02; material harm is gain <−0.02. Report missed useful escalations with their denominator, harmful escalations, per-system means and all seed-level values. Primary effects: benefit minus random/uncertainty policy loss, coverage, missed-benefit rate, and LLM versus projection loss. Display all fixed threshold-grid points without selecting one on test.

Average seeds within systems before averaging test systems. For interval displays, resample test systems with all their seeds together, 10,000 bootstrap draws, seed 20260926, percentile 95% intervals for prespecified paired mean differences. Eight test groups can still give unstable intervals; report group count and individual-system effects. No seed-level independent-sample tests, post-hoc subgroup claims, novelty promise, or assertion of equivalent quality from nonsignificance. If incomplete paired denominators prevent evaluation, publish failure/status counts and do not substitute a complete-case primary policy result.

## Reliability and resources

Keep serial local inference, no paid/cloud endpoint, no credentials, no new model download. No retries; a malformed returned batch uses the documented classical fallback for five charged acquisitions and remains labeled fallback. Provider failure/timeout stops the stage with all unattempted runs retained. Count actual attempts, dispatches, tokens when known, raw text, legal-token schedule, projections, duplicates/collisions, fallbacks, startup and runtime. Unknown is not zero. Any resume after failure requires an explicit audited checkpoint plan, never deletion/reset of traces.

The design needs **203 new calls**: 20×5×2 plus three synthetic format checks. The existing follow-up allowance has only 34 calls and approximately 644 seconds remaining before this stage's diagnostic. Therefore it cannot run under current caps. A prospective additional-stage ceiling of 203 calls and 60 minutes is a **proposal, not authorization**; larger worst-case timeout totals may force incomplete denominators even under that proposed limit. The v3 mean of about 9.51 seconds/request suggests roughly 32.2 minutes of request time alone for 203 calls; this is a planning estimate, not measured v4 cost or a guarantee. Dataset widths/hardware can change runtime substantially.

Preserve historical cumulative ledgers. A future authorized stage needs its own explicit allowance record plus cumulative accounting; no reset. Actual training/paired collection, synthetic gates and failures are separate from deployment estimates selecting only prefix + controller + selected branch. Loading/warm-up is separate; no cloud-dollar savings inferred from local token counts.
