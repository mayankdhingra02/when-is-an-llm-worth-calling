# Frozen pilot protocol v1 — 2026-09-24

Freeze occurs before optimizer outcomes; SHA-256 recorded in run manifests. Scope is an offline, transductive, single-objective smoke pilot, not a numerical SNAP2 replication or a credible test of router generalization. No tuning after looking at outcomes.

## Selection and split

Select the three explicitly named application tables Apache_AllMeasurements, SQL_AllMeasurements (SQLite headers), and X264_AllMeasurements from pinned MOOT. Criteria: real configuration task, numeric finite objective, complete binary configuration, 20–5000 unique configurations, at most 40 variables. No performance-based selection. Keep the first occurrence of each feature vector, regardless of its objective; preserve source row indices and report exclusions. Apache and SQLite are development groups, x264 is the held-out smoke group. All versions, aliases, and seeds must stay in their group. Three groups cannot establish generalization; no inferential p-values or confidence claims.

## Acquisition and classical method

Seeds 11,23,37,53,71; B=20 inclusive of four random initialization labels; t=10. Random search and `ezr_centroid_adapted` use private random generators and the same initial shuffle within a task/seed. All features in these tables are symbolic binary settings according to MOOT lowercase headers. Distance is square root of mean mismatches; centroid is column mode (ties smallest value). The adapted EZR best/rest loop follows SNAP2 Algorithm 1: elite size floor(sqrt(n)); next row minimizes distance-to-best minus distance-to-rest; insert into best and evict its worst when oversized. Candidate ties follow initial seeded order. Retain every acquired incumbent. No hidden outcomes, hidden-label statistics or hindsight ranks enter this code.

Online d2h uses only min/max of acquired labels, recomputed as labels arrive. Constant objectives contribute zero. This differs explicitly from current EZR v0.9.4 logistic normalization and from any full-table normalization. For one objective the order remains its observed objective order. No upstream code is executed. Current upstream `acquire` loops budget times AFTER warm start; we instead cap TOTAL labels at 20. The paper's pseudocode sorting direction is inconsistent with its textual prompt; this adaptation consistently minimizes loss.

The oracle owns all objective vectors. Its acquisition method charges each unique row once and refuses duplicates or over-budget queries. The optimizer receives candidate features and copies of acquired observations only. Store a frozen 10-label prefix including elite/rest/order; restore separate classical/LLM states. Shared prefix costs 10 actual accesses; each continuation costs 10 new accesses (30 per pair, even when the branches overlap), plus 20 for the random arm. Report union of distinct queried row IDs separately. This is table-label access, not live application execution cost.

## Scoring

Only the separate retrospective evaluator sees full-table objective extrema. Normalize minimization as (y-min)/(max-min), maximization inversely; d2h = RMS of oriented objective losses. Report best acquired d2h (lower better) and paper-style Delta = 100 * [1 - (d2h-min_all_d2h)/(median_all_d2h-min_all_d2h)]. Undefined denominators produce null, not zero. Q=1-d2h; paired benefit = classical_loss - LLM_loss. Material margin delta=0.02 in normalized d2h, chosen before outcomes. This offline table selection cannot score better than the table optimum.
