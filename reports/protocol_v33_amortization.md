# V33: model-request recovery thresholds from real cached outcomes

Exploratory cost analysis after V22–V32 outcome exposure. No new optimizer acquisitions, physical measurements, model calls, task selection, model choice or router fitting. The next question is concrete but conditional: if a selected setting is reused for future work, how much baseline work would be needed to recover the observed model request duration? This is not a measured deployment or a promise of savings.

Use every one of the fifteen V22 development prefixes and three unique observed presentations (assigned_ids, reverse_display, reassigned_ids), retaining the exact-repeat fifteen calls in historical collection cost. Primary comparator is fixed sequential3NN from V29; secondary comparators are original full-space centroid, static shortlist rank and adaptive shortlist centroid. All variants/seeds remain with their three exposed software families. No comparator/presentation is selected per case after observing a winner. Primary presentation remains assigned_ids. Preserve all gains, ties and harms.

For each same-prefix pair, acquire no new labels: let b and l be the minimum positive recorded targets in the classical and real LLM arms, respectively; define g=(b−l)/b. C is that exact observed model request's wall_seconds, not generation_seconds, not a token-price estimate. Require complete provenance/model revision, raw output-to-selection mapping, shared prefix, twenty distinct acquired rows, cache key, status, usage and observed finite cost. Missing cost is an error, never zero. Freshly replay the existing local-tokenizer V22 provenance verifier without inference and retain its log. Freeze inputs/code/tests before this analysis.

Define a hypothetical reuse scenario with S seconds of future work under the classical-selected configuration. ASSUMPTIONS: the recorded target ratio transfers linearly to future elapsed work, configuration quality is equally acceptable, outcomes persist, and all other differential optimization/deployment costs cancel or are excluded. Net request-time-adjusted saving is S*g−C seconds. For g>0, equality occurs at S*=C/g; strictly positive saving needs S>S*. For g<=0 there is no finite recovery threshold. These units avoid assuming the source table's absolute time units, but do not validate the proportionality/quality assumptions. No cloud dollars, live speedup, learned policy or application utility is inferred.

Report per-case thresholds for assigned_ids; an explicitly hypothetical equal-probability one-presentation scenario using mean(g),mean(C); and recovery under every one of the three observed presentations, max(C_j/g_j), only if all g_j>0. The mean scenario is one random presentation/call, not a three-call ensemble; max thresholds are not mean thresholds. Raw observations remain separate from modeled columns. Observed post-call cost is evaluation evidence and never a predecision input.
