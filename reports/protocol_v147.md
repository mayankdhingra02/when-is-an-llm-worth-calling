# V147: retrospective nested family validation on the paired two-model cohort

This analysis plan is written after V141–V145 outcomes were inspected. It is an exploratory reanalysis, not a new prospective holdout or a preregistration. No family, model, or case is chosen for its gain. Include all 30 V141 paired cases and all 25 V144–V145 Spark cases per model: seven families, 55 cases/model. All five Spark workloads and all seeds remain together. Keep the interrupted SmolLM case with its recorded classical fallback. Main sequential and adaptive comparisons are complete; the missing random-row comparator is not used as a routing target.

No new model requests, objective acquisitions, native trials, packages, or downloads. Reuse only sealed real measured evidence. The primary target is relative LLM gain over sequential3NN, oriented consistently with the original metric. Adaptive-neighbor gain is a secondary reported contrast and is never used for fitting or threshold selection. Joint >1% benefit is diagnostic. Inputs are exactly the seven V132 pre-decision features recomputed from each B10 prefix and the feature domains. For Spark use actual candidate-domain cardinality, not the ten-level proposal grid. Do not use workload/system identity, model responses, projection statistics, or continuation labels as features.

Fit each model's router separately. Outer leave-one-system-family-out has seven folds; each fold uses only the other six families for training. Inner leave-one-family-out on those six generates development scores. Standardization and ridge fitting use equal family weight, fixed alpha=1; no hyperparameter search. Three declared feature sets: all seven (primary), remove domain cardinality (ablation motivated by the exposed Spark support audit), trajectory only (last four, secondary). All variants are reported; no winning variant is rebranded as confirmatory.

For each variant, choose the threshold from zero, family-weighted development-score quantiles 0/25/50/75/100%, and never-call. Maximize equal-family inner validation gain; within 1e-12 prefer fewer family-weighted calls, then the higher threshold. Refit on the six outer-training families and apply that fixed threshold to the untouched outer fold. Uncertainty-only uses the final pre-decision bootstrap dispersion with the same development-only threshold procedure. Never/always remain controls. As a declared diagnostic against trivial no-call solutions, additionally apply the development 80th-percentile score threshold for all-feature benefit and uncertainty; do not choose a test quantile or force a test call count. This is nominal development-rate calibration, not exact deployment rate control.

For every nonconstant policy, compare its realized gain with outcome-independent random escalation matched to its exact call count within each held family. Analytic expectation equals call fraction times family mean gain. Save one fixed-seed realization and 10,000 fixed-seed random subsets for a descriptive 95% reference band, not a population confidence interval or confirmatory p-value. Family weighting is primary; pooled seed means are sensitivity only. Report family-level gains, call counts, >1% harmful calls, missed >1% gains, joint wins, and hindsight headroom. Show leave-one-family-out sensitivity of the aggregate and support-range extrapolation counts. Seven heterogeneous, previously exposed families do not establish journal readiness or rule out useful routing on other systems.

Input snapshots, protocol, implementation and synthetic tests are hashed before the first new fit. Folds retain training keys, feature transformations, inner predictions, calibration grids and outer decisions. Test held-family outcome perturbations must not alter its fitted model, threshold or decisions. Duplicate/missing pairs and any grouping/hash/prefix inconsistency fail closed. Computation cap 600 seconds for the analysis; figures/replay/tests separate. No indefinite jobs.

Costs: new reanalysis has zero collection cost; its wall/CPU time is recorded. Historical collection comprises 110 actual generation starts (109 complete, one interrupted) and 1,100 model-continuation acquisitions plus original prefix/control collection in the cited ledgers. Historical inference is not free. Report hypothetical selected-branch request counts and measured historical per-request timing/usage as replayed deployment estimates; exclude future usage from policy inputs. Unknown usage stays unknown. Do not infer cloud dollars or native-time savings.
